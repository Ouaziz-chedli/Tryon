Point d'entrée pour tout agent travaillant sur ce repository.

1. **Lire d'abord [README.md](README.md)** pour la vue d'ensemble du projet (**Team `TRYON`** — European AI Championship Paris 2026) et les liens vers toute la documentation.
2. **Consulter [docs/README.md](docs/README.md)** pour les fiches détaillées des 3 tracks, des papiers de recherche et du setup cluster GPU Jülich (`JURECA`, projet `training2666`).
3. **Règles du repo :**
   - Ne jamais commiter de poids de modèles (`.pt`, `.pth`, `.npz`), de datasets ou d'environnements (`.venv/`) — déjà couverts par `.gitignore`.
   - Ne pas consommer de requêtes sur les endpoints évalués de la Track 2 (`ep-01` à `ep-33`, budget strict de 100 réponses/endpoint) avant validation sur `ref-01` à `ref-09`.
   - **Soumissions serveur (cooldowns) :** Track 3 Unlearning = **15 minutes** ; Track 1 Watermark = **10 minutes** ; soumission échouée = **2 minutes** (ne soumettre qu'un checkpoint validé localement via le harnais ; `API_KEY` dans `infra/team-access.md`).
   - **Cluster JURECA/Sispa (`training2666`, Team `TRYON`) — doctrine Chef (`2026-11-22 05h20`) :**
     - *Réservation `cispahack`* (30 nœuds exclusifs 4 GPUs réservés aux équipes) : **NE PAS y faire la queue** (Chef, `2026-11-22 06h25`) — tout job TRYON va sur la **partition GPU générale** (`dc-gpu`, nœuds partagés, sans plafond, ne compte pas dans la limite d'équipe). Historique : règle « 1 seul job réservation » désormais inapplicable car on n'y soumet plus.
     - **HORS réservation (les ~120 GPU / 30 nœuds réservés aux équipes) : TOUS les GPU du cluster disponibles sur la partition générale sont utilisables par TRYON, SANS plafond artificiel** — consigne du Chef (`2026-11-22 05h25`) : « tous ceux qui sont dans le cluster en dehors de cette réservation, on peut s'en servir, donc on les prend ». Nœuds partagés, pas de contrainte d'exclusivité ; vérifier le nom de partition via `sinfo` et la charge via `sinfo -o "%P %a %D %G %t"`.
     - **Mode opérationnel (Chef, `06h40`) : « on prend les GPU libres, c'est tout »** — avant chaque `sbatch`, vérifier `sinfo -h -o '%P %t %D %N' | grep -v alloc` et cibler une partition avec des nœuds **idle** (ex. `dc-gpu-devel` souvent libre, `MaxTime=UNLIMITED`) ; ne jamais laisser un job attendre si des GPU dorment ailleurs.
     - **Réservation `cispahack` RÉ-OUVERTE (Chef, `09h30`) : « prenez aussi les GPU de la réservation, ce qui est disponible on le prend — laissez-en quand même 4 de libres ».** Cap : ne jamais dépasser (GPU libres résa − 4) utilisés par TRYON ; vérifier `squeue -r --reservation=cispahack` avant chaque soumission résa. Règle d'or scancel : vérifier l'état RUNNING/COMPLETING avant toute annulation (incident 15905361 : 5 tasks tuées au moment exact de leur allocation).
     - **Note admin cluster (`10h05`, via Antigravity) :** Slurm peut backfiller des jobs `dc-gpu` généraux **sur les 30 nœuds réservés** `cispahack` — pour forcer la file générale uniquement : `--exclude=jrc[0198,0215,0217,0231-0233,0245,0257-0258,0283,0314,0321,0323-0324,0327,0329,0347,0349-0350,0362-0363,0374,0387,0394,0396,0410,0414,0423,0442,0444]`. **PIÈGE CRITIQUE : ne JAMAIS combiner `--exclude` avec `--reservation=cispahack`** (exclurait les 30 nœuds de la résa ⇒ `ReqNodeNotAvail` infini) — soumettre les résa avec `--exclude=""` si le script porte l'exclusion en dur. Le `fleet_scheduler` injecte l'exclusion automatiquement sur les soumissions générales uniquement.
     - **Règle GPU (Chef, `11h10`) : « 1 nœud et 4 GPU par job — jamais 1 GPU, sinon c'est du gaspillage »** — sur les nœuds exclusifs (résa ET exclusifs généraux), un job `--gres=gpu:1` abandonne 3 GPU que personne d'autre ne peut utiliser. Toute soumission : `--nodes=1 --gres=gpu:4`, avec les workers qui se répartissent les 4 GPU (`CUDA_VISIBLE_DEVICES=$gid`). Les jobs multi-configs = UN job multi-workers, PAS un array de tâches 1-GPU.
   - **Google Colab :** **maximum 3 sessions simultanées** (Chef, `2026-11-22 05h20`) et le budget CU doit tenir **en permanence** — `colab stop` systématique dès qu'un run est collecté, `colab usage` avant toute création.
